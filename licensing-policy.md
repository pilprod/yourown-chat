# Licensing and upstream provenance policy

Source code, dependencies, features, and build inputs may be used only when
their licenses permit the intended use, modification, deployment, and
distribution.

Copyright notices, license texts, attribution, product notices, and
corresponding-source obligations must be preserved. An agent must not remove,
hide, or bypass licensing or edition enforcement.

A maintained fork records the exact upstream revision, keeps local
modifications identifiable, and preserves a reproducible path from upstream
source to the released artifact.

Commercial or Enterprise source and features require a verified entitlement
that covers the intended environment and use. Uncertainty about licensing
blocks the affected release until the user resolves it.

Release evidence includes the applicable license verification, notices, source
revisions, local patch provenance, SBOM, and artifact digest.
