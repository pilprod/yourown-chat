# Инфраструктура сервера YourOwn.Chat

Этот документ фиксирует целевое состояние пилота после перехода на собственную
серверную авторизацию. Mattermost остаётся средой совместной работы, но больше
не является источником личности пользователя платформы.

## Состав пилота

| Часть | Размещение | Назначение |
|---|---|---|
| `transport` | пространство `server-edge` | Принимает дополнительно зашифрованные запросы клиента, защищает от повторов и передаёт их разрешённому внутреннему сервису |
| `auth` | пространство `server-edge` | Проверяет вход через закрытый интерфейс сервиса личности и выпускает непрозрачный прикладной сеанс |
| `api` | пространство `server-identity` | Хранит пользователей, хеши паролей, связи с рабочими пространствами и пользователями Mattermost |
| `admin` | пространство `server-identity` | Выполняет только внутренние административные операции по отдельному служебному токену |
| `migrate` | пространство `server-identity` | Применяет схему базы и один раз создаёт первого пользователя |
| `control` | пространство `server-control` | Отдаёт клиенту пользовательские функции управления агентами и долговременными процессами |
| PostgreSQL | существующий минимальный Cloud SQL | Отдельная логическая база и отдельная роль для данных личности |

Каждое пространство имеет запрет входящего и исходящего трафика по умолчанию.
Межпространственные соединения разрешены только между точными парами
пространство–метка приложения и только на нужный порт.

## Поток входа

```text
нативный клиент
  → transport: дополнительно зашифрованный запрос
  → auth: POST /v1/sign-in/password
  → api: внутренняя проверка имени или почты и пароля
  → auth: непрозрачный сеанс yoc_…
  → защищённое хранилище устройства
```

Пароль не отправляется по обычному открытому прикладному маршруту. Для сервера
YourOwn.Chat дополнительное шифрование обязательно; для подключаемого
Mattermost оно остаётся настраиваемой возможностью рабочего пространства.

Сервер не отдаёт клиенту токены сторонней системы личности и не открывает
встроенную веб-страницу входа. Адрес `auth.yourown.chat` используется только
для метаданных привязки приложения к домену. Чувствительный маршрут доступен
исключительно внутри зашифрованного транспорта.

## Пользователи и связь с Mattermost

Пользователь YourOwn.Chat имеет собственный устойчивый идентификатор,
уникальное имя, почту и хеш пароля. Связь с Mattermost хранится отдельно и
содержит как минимум:

- идентификатор рабочего пространства;
- адрес сервера Mattermost;
- идентификатор пользователя Mattermost;
- состояние и время последней проверки связи.

Отключение или замена Mattermost не удаляет личность YourOwn.Chat. Одна
платформенная личность в дальнейшем сможет иметь несколько связей с рабочими
пространствами.

## Первый пользователь

Платформа создаёт только одного начального пользователя `pilprod`. Случайный
временный пароль создаётся Terraform, хранится в защищённом собственным ключом
Secret Manager и доступен только заданию `migrate` через отдельную рабочую
учётную запись. Повторный выпуск не меняет пароль уже существующего
пользователя.

После первого успешного входа временный пароль необходимо заменить. Открытая
регистрация пилота выключена. Следующие пользователи создаются через
прикладной административный процесс с подтверждением и журналом действий.

## Аппаратные ключи доступа

Текущий минимальный выпуск реализует нативный вход по имени или почте и паролю.
Аппаратные ключи доступа не входят в этот переходный выпуск: для них серверу
нужны собственные таблицы открытых ключей, проверка вызова, счётчика и
происхождения, а клиенту — нативный интерфейс системной авторизации. До
реализации этого полного контура интерфейс не должен показывать такую кнопку.

## База и секреты

Используется существующий минимальный экземпляр Cloud SQL, без отдельного
оплачиваемого экземпляра. Изоляция обеспечивается логической базой, отдельной
ролью, отдельными строками подключения и сетевыми правилами.

Секреты монтируются через драйвер Secret Manager и рабочие учётные записи.
Они не хранятся в исходном коде, образах, параметрах командной строки или
обычных объектах настройки Kubernetes. Ключ дополнительного транспорта и
начальный пароль защищены собственным ключом шифрования платформы.

## Сетевые границы

Разрешённые основные соединения:

| Источник | Назначение | Порт |
|---|---|---:|
| входной контроллер | `transport` | 8080 |
| входной контроллер | открытые метаданные `auth` | 8080 |
| `transport` | `auth` | 8080 |
| `transport` | разрешённые рабочие пространства Mattermost | 443 |
| `auth` | `api` | 8080 |
| `api`, `admin`, `migrate` | частный адрес Cloud SQL | 5432 |
| все необходимые модули | служба имён кластера | 53 |

Прямой входной маршрут к `api`, `admin`, `migrate` и `control` отсутствует.
Административные маршруты отделены от пользовательского двоичного файла.

## Ресурсы пилота

Для малых сервисов начальные запросы процессора и памяти задаются по наблюдаемой
нагрузке, а не по верхнему пределу. Пределы оставляют запас на кратковременный
запуск, но не резервируют его на узле. Значения пересматриваются по фактическим
метрикам после испытаний на устройстве.

## Выпуск

Исходный код сервера собирается только управляемой платформой Cloud Build.
Образ проходит тесты, проверку уязвимостей и аттестацию, после чего один тег
версии запускает отдельный выпуск сервера. Репозиторий приложения не содержит
собственного процесса непрерывной сборки.

Порядок перехода:

1. выпустить сервер с нативной авторизацией;
2. создать начальный секрет и дать его только заданию миграции;
3. применить схему базы и создать `pilprod` без замены существующего пароля;
4. развернуть новые `transport`, `auth` и `api`;
5. проверить вход с физического устройства и получение непрозрачного сеанса;
6. удалить прежний внешний сервис личности, его пространство, базу, секреты и маршруты;
7. удалить переходные объявления Terraform после подтверждения пустого состояния.

Откат приложения не должен возвращать удалённую систему личности. При
неудачном выпуске откатывается только совместимая версия собственных сервисов,
а данные пользователя сохраняются в отдельной базе.
